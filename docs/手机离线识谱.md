# 手机离线识谱 0.3.0

导入图片或PDF后选择“手机识谱”。全部模型和依赖来自安装包，不上传乐谱。多页PDF按原始页序处理，每页完成后保存MusicXML；再按页序及页内小节顺序合并，保留每个小节的来源页。打开新乐谱时练习范围重置为从开头至结尾，预览响应绑定乐谱ID、页码及请求编号，忽略旧请求。

## 后台处理

`RecognitionService`是用户主动启动的Android前台服务，持有CPU唤醒锁，通知显示进度并可取消。它单独创建识谱WebView，使用 `omr-engine.html/js` 调度Python和ONNX工作线程；Activity仅显示状态，不拥有模型任务。页面导航、手机旋转或Activity销毁不会主动取消服务。强制停止或系统终止进程后计算会中断，再次开始复用同份原文件已经完成的页面。拒绝通知权限时仍可从应用内查看进度。

每次仅运行一个识别任务，一次支持1–40页。尚未完成的页需重做；正在识别的文件不接受同时保存校对，删除会取消该任务。同步曲库仓库防止后台识别与其他乐谱编辑覆盖彼此。

## 识谱运行通道

本地资源源 `https://appassets.androidplatform.net/` 映射至APK资产，不是外部网站。资源拦截器拒绝其他主机和不安全路径，未配置网络回退。

Python/Pyodide/homr工作线程处理图像、谱表和MusicXML生成，独立ONNX Runtime Web线程以单线程WASM/CPU运行模型。普通同步Python调用通过原生响应流等待推理结果，返回包以512KiB分块写入，最大64MiB。取消和超时释放等待者，不需要JSPI、SharedArrayBuffer或跨源隔离，不监听网络端口。

经典Blob启动脚本动态导入包内模块，避免旧WebView模块线程问题。头页保留严格脚本CSP；不得添加data:脚本源，否则会改变Pyodide的工作线程类型探测。0.2.2修复的Windows ZIP资源路径规范化继续保留。

## 播放和练习

MusicXML解析保留声部、音符独立时长、延音与速度变化。PlaybackTimeline生成按音乐时间排序的播放计划，支持左右手与小节范围、装饰音短奏、跨小节延音合并；播放使用采样钢琴，不改变练习判定或成绩。正BPM按原曲速度比例缩放各速度段，变速时保持相同音乐位置。反复及跳房暂不展开。

逐音练习只绘制当前一个音符。小节练习显示当前小节，以黄色竖线和底色标记当前事件；错音仍等待，和弦可逐键补齐。

## 资源与验证

运行信息可从设置复制。生产运行时、模型和原始许可证在 `app/src/main/assets/local-omr/`；校验入口为 `tools/mobile-omr/verify.py`，APK字节一致性及Windows ZIP路径检查为 `tests/audit_apk.py`。每次发布应分别保留当次验证报告，旧版真机结果不能代表新版已完成验证。

识谱仍需手动校对，尤其是复杂声部、装饰音、调号和延音；速度与准确度以实际设备为准。
